기록일: 2026-09-16 KST

## 범용 인터페이스와 Markdown 작업 흐름

- 조사 단계부터 페이지·API·지표·테이블 단위로 Markdown 파일 분류. 원본은 workspaces/{company}/{product}/{run} 아래 보관.
- 회사 서식, 제품 설정, 환경 연결, 문서 계약, 역할, 단계 규칙 분리. 폰트·제목·표 여백·테두리·머릿글·바닥글·마지막 페이지는 회사 테마에서 적용.
- 12단계: 범위 → 목록 조사 → 구조 조사 → 화면 조사 → API/지표/데이터 조사 → 불일치 정리 → 목차 → 집필 → 사실 검증 → 독립 리뷰 → 서식 검증 → 전달.
- 단계별 담당자·필수 파일·필수 제목·출처·판정 검사. 통과 파일 변경 시 재작업 필요. 문서별 작성 에이전트 설정 예시 제공.
- 외부 AI 실행은 하지 않음. 역할별 task packet과 근거 패킷 생성까지 구현. 담당자 ID는 감사용이며 사용자 인증 기능은 아님.
- Markdown 제목·표·코드·강조 안내·등록된 로컬 PNG/JPEG 지원. 전체 GFM 문법을 지원하지는 않음.

## 수집 구현

- Python 3.12 조정 프로세스가 Node Playwright 프로세스를 병렬 실행. 페이지 분배·긴 화면 분할·민감 영역 마스크·실패 기록·시간 제한 구현.
- 제품/환경별 인증 변수 분리. 비밀번호를 설정 파일에 저장하지 않음.
- PostgreSQL은 임의 SQL 대신 승인 테이블/컬럼의 구조화된 조회만 허용. READ ONLY 트랜잭션, 권한 검사, 행·시간 제한 적용.
- DB 읽기 전용 역할과 승인된 객체/함수의 안전성은 운영 DB에서 보장해야 함. 실제 DB 접속 정보가 없어 연결·서버 실행은 미검증.

- 분류된 Markdown 테이블 예제 6개 절 컴파일 성공. 조사 단계 통과로 위장하지 않고 검토본으로 생성.

## 실제 예제

생성 명령: `./tools/run.ps1 -Action build -Formats pdf,docx`

실행 폴더: `output/DATA-DEMO-001-20260915T145847Z-f0f30b95`

PDF: Poppler로 5쪽 렌더링, 모든 페이지 이미지 육안 확인. 한글 누락·표 잘림·겹침 없음. 표지·구성 목록·내용 2쪽·마지막 페이지를 확인했다. 이 검수는 해당 PDF에 한정하며 모든 테마와 입력의 레이아웃 보장을 뜻하지 않는다.

DOCX: 생성은 성공. 패키지 `render_docx.py` 실행은 아래 오류로 exit 1.

```text
FileNotFoundError: LibreOffice soffice.exe was not found on PATH
```

이 Windows 번들에는 LibreOffice가 없으며 사용자 설치 Office나 다른 변환기를 임의 사용하지 않았다. DOCX는 미검증 초안이다. PDF는 독립 ReportLab 출력이므로 DOCX 시각 검수의 대체 증거가 아니다.
