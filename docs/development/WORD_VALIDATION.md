# DOCX 실제 렌더링 검증

검증일: 2026-09-16. 대상은 별도 로컬 테스트 제품의 사용자 매뉴얼, 기능 명세서, API 명세서, 지표·계산식 명세서, 테이블 명세서다.

**최종 판정: Word 07의 5종 92페이지가 LibreOffice 시각 검수를 통과했다.** 사용자 매뉴얼 16쪽, 기능 명세서 17쪽, API 명세서 25쪽, 지표·계산식 명세서 16쪽, 테이블 명세서 18쪽이다. 각 역할의 전체 페이지 검토에서 신규 결함은 발견하지 않았다.

## 환경과 방법

사용자 승인으로 Windows에 LibreOffice 26.8.0.3을 설치했다. 공식 배포 설치 파일을 사용했으며 새 폰트를 설치하거나 저장소에 복사하지 않았다. Python 3.12에서 DOCX를 생성하고 LibreOffice로 실제 DOCX를 렌더링한 페이지 PNG를 검토했다. 별도로 생성한 ReportLab PDF를 Word 검증 근거로 사용하지 않았다.

일반 사용자, 개발자, 데이터 담당자 역할이 각 문서의 모든 페이지를 읽었다. 문장·표 셀·숫자·수식·SQL·캡처·머릿글·바닥글을 확인하고, 전체 회차의 문제 기록을 마친 뒤 수정했다. 수정 후 다섯 문서를 모두 새 폴더에 생성해 같은 범위를 다시 확인했다. 원본 문서와 이전 회차는 보존했다.

## 회차별 기록

| 회차 | 전체 페이지 | 발견·조치 |
| --- | ---: | --- |
| Word 01 | 87 | 기본 템플릿 테마 글꼴이 회사 글꼴을 덮어쓰는 문제, 짧은 표 행 분할, 표지 단어 분절 확인 |
| Word 02 | 89 | 글꼴·행 분할 해결. 열 너비, 표지 장식선·분절, 짧은 마지막 절 배치 수정 요청 |
| Word 03 | 96 | 표지 개선. 소진된 generator로 짧은 절을 검사해 긴 절까지 묶는 회귀 및 좁은 설명 열 발견 |
| Word 04 | 88 | 블록 목록 보존으로 소제목 고립 해결. 한글 단어 줄바꿈 추가 확인 |
| Word 05 | 89 | 한국어 언어 태그로 어절 분절 해결. 영문·시각·숫자 단위와 좁은 설명 열 보완 |
| Word 06 | 93 | URL·숫자 단위 해결. 최소 열 너비의 일괄 적용으로 긴 테이블명이 분절되어 재조정 |
| Word 07 | 92 | 설명 열과 짧은 값 열을 구분하여 공간 배분. 전체 역할별 재검수 통과 |

Word 04·05에서 제기된 설비 코드와 기대값 밀착 한 건은 원본 PNG를 한 장씩 다시 열어 대조한 결과 오탐이었다. 해당 보고서에 철회·정정 이력을 남겼으며 실제 결함으로 집계하지 않는다.

회차별 원본·렌더링 manifest·역할별 독해 보고서는 저장소와 같은 상위 경로의 `_test_product/validation/word-review-01`부터 순서대로 보관한다. 이 경로는 가상 테스트 전용이며 제품 정책이나 운영 문서가 아니다.

## 내용 보존과 회귀

- 최초 DOCX 5종의 SHA-256이 그대로 유지됐다. 수정 출력은 별도 폴더에 생성했다.
- 최종 출력의 본문 452문단과 표 1,163셀을 공백·개행 정규화 후 대조해 단어 순서가 동일함을 확인했다. 코드 18문단은 공백을 포함해 동일하며 외부 링크 대상도 같다.
- Python 3.12 전체 단위·통합 테스트 75개 통과, skipped 0, 33.747초.
- 실제 테스트 비밀번호 검사 4,931파일에서 0건. 비공개 `.local`과 Git 내부는 제외하고 DOCX·XLSX 압축 내부는 포함했다. 모든 가능한 비밀 유형의 부재를 보증하는 검사는 아니다.

## 검증 범위의 한계

- LibreOffice 호환 렌더링 결과다. Microsoft Word 앱 자체의 결과는 미검증이다.
- Excel 시트의 앱 시각 검수는 이번 작업에 포함하지 않았다.
- 회사별 실제 양식·글꼴·다른 언어와 제품 데이터로는 별도 검수해야 한다.
- DOCX 목차는 절 목록이다. 자동 페이지 번호 목차는 미지원이다.
- 원문 내용의 승인과 워크플로 전달 승인은 서식 검증으로 자동 처리하지 않는다.

## 재현 자료

테스트 제품의 `tools/rebuild_word_review.py`는 보존된 Markdown을 현재 DOCX 어댑터로 다시 생성하며 `tools/render_word_review.py`는 새 폴더에 실제 렌더링 결과와 원본 해시를 기록한다. 출력 폴더는 덮어쓰지 않는다. Python 회귀 테스트는 저장소에서 `python -m unittest discover -s tests -v`로 실행한다.

한 페이지보다 긴 130줄 표 행의 텍스트 유지도 별도로 검사했다. 9페이지 렌더링에서 130개 식별 줄과 마지막 행이 모두 남았다. 이 검사는 텍스트 유지 검사이며 9페이지 전체 시각 승인으로 기록하지 않았다. 행 분할 제어의 의미는 [Microsoft의 cantSplit 문서](https://learn.microsoft.com/en-us/dotnet/api/documentformat.openxml.wordprocessing.cantsplit?view=openxml-3.0.1)를 따른다.
