# 일반 사용자 매뉴얼 작성 가이드

## 1. 문서 목적

본 문서는 시스템의 **일반 사용자용 User Manual 작성 기준**을 정의한다.

매뉴얼은 개발 구조를 설명하는 문서가 아니라 사용자가 화면을 보고 다음 내용을 이해할 수 있도록 작성한다.

* 화면의 목적
* 화면 구성
* 조회 및 조작 방법
* 위젯 및 지표의 의미
* Drill-down 및 상세 정보 확인 방법
* 설정 방법
* 사용 시 주의사항

다음과 같은 개발 내부 정보는 사용자 매뉴얼에서 제외한다.

* API URL
* API Parameter (`from`, `to` 등)
* SQL / Query
* DB Table / View / Function
* 내부 데이터 처리 로직
* 구현 구조

내부 구현 방식은 제외하되, 사용자의 입력·결과 해석·오류 대응에 필요한 기준은 포함한다.

본 문서는 작성 가이드이다. 예시의 화면명·기능·수치는 실제 제품 사양을 의미하지 않는다. 실제 매뉴얼에는 확인된 동작과 지원 범위만 작성한다.

---

### 예시를 읽는 방법

이 가이드의 보충 예시는 가상의 **설비 모니터링 시스템**을 사용한다. 화면 이름과 수치, 지원 기능, 안내 문구는 작성 방법을 보여주기 위한 가정이며 실제 제품의 지원 사양이나 검증 결과가 아니다.

| 예시 화면 | 메뉴 위치 | 작성 유형 | 주요 작업 |
| --- | --- | --- | --- |
| Performance Summary (`PERF-01`) | Monitoring → Performance Summary | Dashboard | 가동률 추이 확인 및 상세 이동 |
| Alarm History (`ALM-01`) | History → Alarm History | Workflow | 알람 검색, 상세·로그 확인, 내보내기 |
| User Settings (`SET-01`) | Settings → User Settings | Configuration | 내 화면의 자동 갱신 간격 변경 |

**문장 작성 예시**

| 부족한 설명 | 사용자에게 필요한 설명 |
| --- | --- |
| 데이터를 조회합니다. | Period와 Equipment를 선택한 후 Search를 누릅니다. |
| 오류가 발생할 수 있습니다. | “조회에 실패했습니다”가 표시되면 네트워크 연결을 확인한 후 Search를 다시 누르세요. |
| 데이터가 없습니다. | `-`는 계산에 필요한 데이터가 없다는 뜻입니다. 실제 측정값이 0인 경우와 구분합니다. |

# 2. 전체 문서 구조

```text
User Manual
│
├─ 1. Introduction
│  ├─ Manual Overview
│  ├─ System Overview
│  ├─ Target Users
│  ├─ Login / Access
│  ├─ Supported Environment
│  └─ Page Feature Matrix
│
├─ 2. Common Functions
│  ├─ Screen Layout
│  ├─ Search / Filter
│  ├─ Screen States / Data Display Rules
│  ├─ Save / Apply
│  ├─ Common UI
│  │  ├─ Table
│  │  ├─ Chart
│  │  ├─ Tooltip
│  │  ├─ Pagination
│  │  └─ Export
│  └─ Drill-down
│     ├─ Drill-down Usage
│     ├─ Detail View
│     └─ Log Tracking
│
├─ 3~N. 실제 시스템 메뉴 구조
│  ├─ Menu
│  │  ├─ Page
│  │  └─ Page
│  └─ Menu
│
├─ Troubleshooting / Contact
│
└─ Appendix
   ├─ A. Glossary
   ├─ B. KPI / Metric Definitions
   ├─ C. KPI Formulas
   └─ D. Reference Index
```

최종 목차는 `Dashboard / Workflow / Configuration` 유형별로 묶지 않고 **실제 시스템 메뉴 구조와 동일하게 구성하는 것을 원칙**으로 한다.

페이지 유형은 목차 분류가 아니라 **페이지별 작성 템플릿을 선택하기 위한 기준**으로 사용한다.

---

### 목차 적용 예시

예시 시스템의 실제 메뉴가 Monitoring / History / Settings라면 다음 순서로 작성한다. 아래 목차는 작성 가이드 자체의 목차가 아니라 최종 사용자 매뉴얼의 예시다.

```text
1. Introduction
2. Common Functions
3. Monitoring
   3.1 Performance Summary
4. History
   4.1 Alarm History
5. Settings
   5.1 User Settings
6. Troubleshooting / Contact
Appendix
```

# 3. 페이지 유형

페이지는 기능 특성에 따라 다음 3가지 유형으로 구분한다.

| 유형                 | 핵심 질문      | 작성 중심        |
| ------------------ | ---------- | ------------ |
| Dashboard Page     | 무엇을 보여주는가? | Widget / KPI |
| Workflow Page      | 어떻게 사용하는가? | 사용자 작업 흐름    |
| Configuration Page | 어떻게 설정하는가? | 설정값 / 변경 방법  |

# 4. Dashboard Page Template

조회 조건과 여러 KPI/Chart Widget이 고정 배치된 페이지에 사용한다.

예:

* Performance Summary
* OHT Utilization
* STK Utilization
* Alarm Statistics

## 4.1 Overview

페이지의 목적과 사용자가 이 화면에서 확인할 수 있는 내용을 2~3문장으로 설명한다.

**작성 예시 — Performance Summary**

> Performance Summary에서는 선택한 기간과 설비의 가동률을 확인할 수 있습니다. Performance Trend에서 시간에 따른 변화를 확인하고, 차트의 특정 지점을 선택하여 해당 시간대의 상세 기록을 볼 수 있습니다.

## 4.2 Screen Layout

전체 화면 캡처를 사용한다.

```text
┌──────────────────────────────────────┐
│ ① Search Conditions                 │
├──────────┬──────────┬────────────────┤
│ ② KPI    │ ③ KPI    │ ④ KPI          │
├──────────┴──────────┴────────────────┤
│ ⑤ Performance Trend                 │
├──────────────────────────────────────┤
│ ⑥ Detail                            │
└──────────────────────────────────────┘
```

화면 영역에는 `① ② ③ ...` 마커를 사용한다.

## 4.3 Search Conditions

사용자가 화면에서 직접 선택할 수 있는 조건만 설명한다.

| 항목             | 설명                   |
| -------------- | -------------------- |
| Period         | 조회 기간을 선택합니다.        |
| Equipment Type | 조회할 설비 유형을 선택합니다.    |
| Search         | 선택한 조건으로 데이터를 조회합니다. |

내부 API Parameter 이름은 작성하지 않는다.

입력하거나 선택하는 항목에는 다음 기준을 함께 작성한다. 해당하지 않는 열은 생략할 수 있다.

| 항목 | 설명 | 필수 여부 | 기본값 | 입력·선택 기준 |
| --- | --- | --- | --- | --- |
| 조회 기간 | 데이터를 조회할 기간 | 실제 기준 | 실제 기본값 | 최대 조회 기간, 미래 날짜 선택 가능 여부 |
| 설비 | 조회할 설비 | 실제 기준 | 실제 기본값 | 단일·다중 선택 여부 |

입력 형식, 허용 범위, 단위 등 사용자가 올바르게 입력하는 데 필요한 기준을 명시한다. 잘못 입력했을 때 표시되는 실제 안내와 수정 방법도 설명한다.

**작성 예시 — 조회 조건을 구체적으로 채운 표**

| 화면 항목 | 설명 | 필수 여부 | 기본값 | 입력·선택 기준 |
| --- | --- | --- | --- | --- |
| Period | 조회할 시작일과 종료일 | 필수 | 오늘 | 시작일·종료일을 포함해 최대 30일. 미래 날짜 선택 불가 |
| Equipment | 조회할 설비 | 필수 | All | 한 설비 또는 All 선택 |
| Search | 선택한 조건으로 조회 | 해당 없음 | 해당 없음 | 조건 변경 후 눌러야 결과에 반영됨 |
| Reset | 조회 조건 초기화 | 해당 없음 | 해당 없음 | Period는 오늘, Equipment는 All로 변경. Search를 눌러 다시 조회 |

> 30일을 초과하면 “조회 기간은 최대 30일입니다”가 표시됩니다. 시작일이나 종료일을 변경한 후 Search를 다시 누르세요.

## 4.4 Widgets

각 Widget이 무엇을 표시하는지 설명한다.

예:

### ② Utilization

설비의 가동 수준을 표시한다.

지표의 상세 정의는 `Appendix B`, 계산식은 `Appendix C`를 참조한다.

### ⑤ Performance Trend

선택한 기간의 성능 변화 추이를 표시한다.

Tooltip을 통해 특정 시점의 상세 값을 확인할 수 있다.

공통 Widget은 중복 설명하지 않고 `Common Functions` 또는 해당 Reference를 참조한다.

**작성 예시 — 위젯 설명 표**

| Marker / 화면 항목 | 무엇을 보여주는가 | 확인·조작 방법 |
| --- | --- | --- |
| ② Utilization | 선택한 기간·설비의 가동률(%) | 정의는 Appendix B, 계산식은 Appendix C 참조 |
| ⑤ Performance Trend | 시간별 가동률 변화 | 지점에 마우스를 올리면 시간대와 가동률 표시. 지점을 선택하면 상세 이동 |
| ⑥ Detail | 선택한 기간의 설비별 상세 기록 | 열 제목을 선택하여 정렬 |

위 표의 Marker는 4.2의 레이아웃에 대응한다. 실제 작성 시에는 실제 캡처에 표시한 번호와 맞춘다.

## 4.5 Drill-down

Drill-down이 존재하는 경우 사용자 관점의 이동 흐름을 설명한다.

```text
Widget 선택
    ↓
Detail
    ↓
Log / 상세 데이터
```

## 4.6 Notes

다음과 같이 사용자가 알아야 하는 데이터 해석 및 조회 관련 주의사항을 작성한다.

* 조회 기간에 따른 집계 단위
* 데이터 갱신 기준
* 권한에 따른 표시 차이
* 데이터 해석 시 주의사항

---

**작성 예시 — Dashboard Notes**

> 조회 결과의 시간은 한국 표준시(KST) 기준입니다. 이 예시 화면의 추이는 조회 기간과 관계없이 1시간 단위로 표시됩니다. 자동 갱신 간격은 User Settings에서 변경할 수 있습니다. 설정 방법은 `SET-01`을 참조하세요.

# 5. Workflow Page Template

조회 → 목록 → 선택 → 상세와 같이 하나의 업무 흐름으로 구성된 페이지에 사용한다.

예:

* Alarm History
* Transfer History
* Inventory 조회
* 검색 + Detail 형태의 페이지

## 5.1 Overview

해당 화면에서 수행할 수 있는 작업을 설명한다.

**작성 예시 — Alarm History**

> Alarm History에서는 선택한 기간에 발생한 알람을 조회할 수 있습니다. 목록에서 알람을 선택하면 상세 내용을 볼 수 있으며, Event Log에서 발생 이후의 상태 변화를 확인할 수 있습니다.

## 5.2 Screen Layout

```text
┌──────────────────────────────────────┐
│ ① Search Conditions                 │
├──────────────────────────────────────┤
│                                      │
│ ② Result List                       │
│                                      │
├──────────────────────────────────────┤
│ ③ Pagination / Export               │
└──────────────────────────────────────┘
```

## 5.3 Search Conditions

화면에 표시되는 조회 조건을 설명한다. 필수 여부·기본값·입력 형식·허용 범위·단위는 4.3의 작성 기준을 따른다.

## 5.4 How to Use

실제 사용 순서 중심으로 작성한다.

```text
① 조회 조건 설정
       ↓
② Search
       ↓
③ Result List 확인
       ↓
④ 대상 선택
       ↓
⑤ Detail 확인
       ↓
⑥ 필요 시 Log 확인
```

필요한 단계에는 각각 캡처를 추가한다.

**작성 예시 — Alarm History 사용 순서**

1. Period에서 `2026-09-01`부터 `2026-09-07`까지 선택합니다.
2. Equipment에서 `OHT-01`을 선택하고 Search를 누릅니다.
3. 발생 시각이 최신인 순서로 표시된 Result List를 확인합니다.
4. 확인할 알람 행을 선택하면 Alarm Detail이 열립니다.
5. Event Log를 선택하여 해당 알람의 상태 변화 기록을 확인합니다.
6. 목록으로 돌아가려면 Back을 누릅니다. 기존 조회 조건·정렬·페이지는 유지됩니다.
7. 필요한 행을 선택한 뒤 CSV를 누르면 선택한 행을 내보낼 수 있습니다. 범위와 제한은 Export 설명을 참조하세요.

캡처 위치 예시: 3단계에는 `[ALM-01] 목록 캡처`, 4단계에는 `[ALM-01-01] 상세 캡처`, 5단계에는 `[ALM-01-02] 로그 캡처`를 넣는다. 이 표시는 촬영 계획이며 실제 캡처가 아니다.

## 5.5 Detail / Popup

Detail 또는 Popup에서 확인할 수 있는 주요 항목을 설명한다.

예:

* 발생 시간
* Equipment
* Event Type
* Message
* Status

**작성 예시 — Alarm Detail 표시 항목**

| 화면 항목 | 표시 예시 | 의미 |
| --- | --- | --- |
| Occurred At | 2026-09-03 10:25:00 | 알람 발생 시각(KST) |
| Equipment | OHT-01 | 알람이 발생한 설비 |
| Message | 이동 경로 장애물 감지 | 발생한 알람의 내용 |
| Status | 해제 | 현재 알람이 해제된 상태 |

> Status는 조회 시점의 상태입니다. 발생 당시부터 상태가 어떻게 바뀌었는지는 Event Log에서 확인하세요.

## 5.6 Notes

조회량 제한, 검색 조건, 작업 시 주의사항 등을 작성한다.

# 6. Configuration Page Template

사용자가 값을 등록/수정/저장하는 설정 페이지에 사용한다.

예:

* Vehicle Parameter
* System Configuration
* User Settings
* Mapping 설정

## 6.1 Overview

어떤 설정을 관리하는 화면인지 설명한다.

**작성 예시 — User Settings**

> User Settings에서는 내 계정의 Performance Summary 자동 갱신 간격을 변경할 수 있습니다. 변경한 설정은 내 계정에만 적용되며 다른 사용자의 설정에는 영향을 주지 않습니다.

## 6.2 Screen Layout

```text
┌──────────────────────────────────────┐
│ ① Search / Target                   │
├─────────────────┬────────────────────┤
│                 │                    │
│ ② Target List   │ ③ Setting Area    │
│                 │                    │
├─────────────────┴────────────────────┤
│                         ④ Save       │
└──────────────────────────────────────┘
```

## 6.3 Setting Items

| 항목        | 설명             |
| --------- | -------------- |
| Target    | 설정할 대상을 선택합니다. |
| Parameter | 설정 항목을 표시합니다.  |
| Value     | 적용할 값을 입력합니다.  |

설정값에는 필수 여부, 기본값 또는 현재값, 입력 형식, 최솟값·최댓값, 단위, 소수점 허용 여부를 필요한 만큼 추가한다. 잘못 입력했을 때의 안내와 수정 방법을 설명한다.

**작성 예시 — 설정 항목**

| 화면 항목 | 설명 | 필수 여부 | 최초 기본값 | 입력 기준 |
| --- | --- | --- | --- | --- |
| Refresh Interval | Performance Summary 자동 갱신 간격 | 필수 | 60초 | 10~300초, 정수만 입력 |

> 화면에는 현재 저장된 값이 표시됩니다. `5`를 입력하면 “10~300초의 정수를 입력하세요”가 표시됩니다. 허용 범위 안의 값으로 수정하세요.

## 6.4 How to Configure

```text
① 대상 선택
    ↓
② 현재 설정 확인
    ↓
③ 설정값 변경
    ↓
④ Save
    ↓
⑤ 결과 확인
```

## 6.5 Save / Apply

Save, Apply, Cancel 등의 동작 차이를 설명한다.

| 항목 | 설명할 내용 |
| --- | --- |
| 저장·적용 차이 | 저장 즉시 반영되는지, Apply가 별도로 필요한지 |
| 적용 시점 | 즉시, 다음 실행, 재접속 등 실제 반영 시점 |
| 적용 대상 | 내 계정, 선택한 대상, 전체 등 영향 범위 |
| 취소·되돌리기 | Cancel이 취소하는 범위와 저장 후 되돌리기 가능 여부 |
| 미저장 상태 이동 | 변경 내용 처리와 확인창 표시 여부 |
| 성공·실패 확인 | 실제 안내 문구, 실패 시 변경값의 상태와 대응 방법 |

여러 화면에서 동작이 같으면 Common Functions에서 한 번 정의하고 개별 화면에는 차이만 작성한다. 저장·적용 기능이 없는 화면에는 작성하지 않는다.

**작성 예시 — User Settings의 저장과 적용**

1. Refresh Interval의 현재값 `60`을 `30`으로 변경합니다.
2. Save를 누릅니다.
3. “저장되었습니다”를 확인합니다.
4. Performance Summary로 돌아가면 30초 간격으로 자동 갱신됩니다.

| 구분 | 예시 화면의 동작 |
| --- | --- |
| Save / Apply | Save로 저장과 적용을 함께 수행합니다. 별도 Apply 버튼은 없습니다. |
| 적용 시점·대상 | 저장 후 Performance Summary에 진입할 때부터 내 계정에 적용됩니다. |
| Cancel | 저장 전 수정한 값을 현재 저장값으로 되돌립니다. |
| 저장 후 되돌리기 | 이전 값으로 다시 입력한 후 Save를 누릅니다. |
| 저장 전 화면 이동 | “변경 내용을 저장하지 않고 나가시겠습니까?”가 표시됩니다. 나가기를 선택하면 미저장 변경이 사라집니다. |
| 저장 실패 | “저장에 실패했습니다. 다시 시도하세요”가 표시됩니다. 입력값은 유지되고 기존 설정은 변경되지 않습니다. |

이 예시처럼 Save가 곧 적용인 화면에 별도의 Apply 절차를 만들어 넣지 않는다.

## 6.6 Notes

설정 변경으로 인해 시스템에 미칠 수 있는 영향이나 권한 등의 주의사항을 작성한다.

# 7. 공통 기능 및 중복 처리

여러 페이지에서 반복되는 기능이나 Widget은 페이지마다 다시 설명하지 않는다.

다음과 같은 기능은 `Common Functions`에서 한 번 정의한다.

* Date Range
* Search
* Reset
* Export
* Table
* Pagination
* Tooltip
* 공통 Chart 조작
* Drill-down 기본 동작

페이지별 Chapter에서는 해당 기능이 일반적인 동작과 다른 경우에만 추가 설명한다.

공통으로 작성할지 여부는 실제 동작이 같은지를 기준으로 결정한다. 작성 기준이 공통이라고 해서 모든 화면의 기능이나 동작이 같다고 가정하지 않는다.

**작성 위치 판단 예시**

| 내용 | 공통 설명 | 페이지별 설명 |
| --- | --- | --- |
| 모든 시간은 KST | 공통 데이터 표시 기준에 한 번 작성 | 다른 시간대를 사용하는 화면만 차이 설명 |
| Search를 눌러 조회 | 공통 조회 방법에 한 번 작성 | 자동 조회되는 화면이 있다면 해당 동작 설명 |
| 상세 이동 시 선택한 시간 구간 전달 | 공통 Drill-down에 기본 원칙 작성 | Performance Trend는 선택한 1시간 구간을 전달한다고 명시 |
| 내보내기 범위 | 형식 선택·다운로드 확인 등 공통 절차 작성 | Performance Summary는 전체 결과, Alarm History는 선택 행이라고 명시 |

## 7.1 조회 및 화면 이동

* 조건을 변경하면 자동 조회되는지, Search를 눌러야 하는지 설명한다.
* Reset이 어떤 기본 조건으로 되돌리는지 설명한다.
* 상세 이동 시 전달되는 기간·조건과 복귀 시 유지되는 필터·정렬·페이지를 설명한다.

## 7.2 화면 상태별 안내

| 상태 | 설명할 내용 |
| --- | --- |
| 조회 중 | 데이터를 불러오는 중이라는 의미와 사용자가 할 수 있는 행동 |
| 결과 없음 | 선택 조건에 해당하는 데이터가 없다는 의미와 조건 변경 방법 |
| 조회 실패 | 실제 오류 안내와 재시도 방법 |
| 권한 없음 | 기능 이용이 제한되는 이유와 권한 요청 방법 |

실제 화면의 안내 문구를 기준으로 의미와 다음 행동을 설명한다. 공통 상태는 한 번만 설명하고 화면별 차이만 추가한다.

**작성 예시 — 화면 문구와 다음 행동**

| 표시 문구 | 의미 | 사용자가 할 일 |
| --- | --- | --- |
| 조회 중입니다 | 선택한 조건의 데이터를 불러오는 중 | 완료될 때까지 기다립니다. 조회 중에는 Search를 다시 누를 수 없습니다. |
| 조회 결과가 없습니다 | 조건에 해당하는 기록이 없음 | Period 또는 Equipment를 변경한 후 Search를 누릅니다. |
| 조회에 실패했습니다 | 결과를 불러오지 못함 | 네트워크 연결을 확인한 후 다시 조회합니다. 계속되면 문제 해결 장을 참조합니다. |
| 접근 권한이 없습니다 | 현재 계정에 이용 권한이 없음 | 시스템 관리자에게 화면 이름과 필요한 업무를 전달하여 권한을 요청합니다. |

> 이 예시에서는 조회 실패 시 이전 결과가 사라지고 실패 안내가 표시됩니다. 이전 결과를 유지하는 실제 제품이라면 그 사실과 이전 결과임을 구분하는 표시를 설명하세요.

## 7.3 데이터 표시 및 해석 기준

| 항목 | 설명할 내용 |
| --- | --- |
| 시간대 | 한국 표준시(KST), UTC, 현장 시간 등 실제 표시 기준 |
| 갱신 기준 | 실시간 여부, 갱신 주기, 마지막 갱신 시각의 의미 |
| 단위 | 초·분·시간·건·백분율 등 |
| 표시 자릿수 | 소수점 표시 자릿수와 반올림 방식 |
| 값 없음 | `0`, `-`, 빈칸 등의 실제 의미와 차이 |

시스템 전체에서 같은 기준은 공통으로 정의한다. 화면·위젯마다 다른 갱신 주기나 단위 등은 해당 항목 또는 Notes에 작성한다. 내부 NULL 처리 코드 대신 사용자가 보는 표기의 의미를 설명한다.

**작성 예시 — 데이터 표시 기준**

| 항목 | 예시 시스템의 안내 |
| --- | --- |
| 시간대 | 모든 날짜와 시간은 한국 표준시(KST) 기준입니다. |
| 갱신 | Performance Summary는 기본 60초마다 자동 조회합니다. User Settings에서 10~300초로 변경할 수 있습니다. Alarm History는 Search를 눌러 조회합니다. |
| Last Updated | 화면에 표시된 결과를 마지막으로 성공적으로 조회한 시각입니다. 원천 기록의 발생 시각을 뜻하지 않습니다. |
| 단위·자릿수 | Utilization은 % 단위이며 소수점 둘째 자리에서 반올림하여 첫째 자리까지 표시합니다. 알람 건수는 정수로 표시합니다. |
| `0` | 계산하거나 집계한 결과가 실제로 0입니다. |
| `-` | 계산에 필요한 데이터가 없어 값을 표시할 수 없습니다. |
| 빈칸 | 해당 기록에 선택 항목이 입력되지 않았습니다. |

표 전체는 설명을 위한 통합 예시다. 실제 문서에서는 공통 기준과 페이지별 차이를 위의 작성 위치 기준에 따라 나눈다.

## 7.4 Export

| 항목 | 설명할 내용 |
| --- | --- |
| 내보내기 범위 | 현재 페이지, 전체 조회 결과, 선택한 행 중 무엇인지 |
| 조건 반영 | 필터·정렬이 파일에 반영되는지 |
| 파일 형식 | CSV, Excel(.xlsx) 등 실제 제공 형식과 확장자 |
| 제한 | 최대 건수와 초과 시 동작 |
| 표시 기준 | 화면과 파일의 시간대·단위·소수점 표시 차이 |
| 결과 확인 | 다운로드 완료·실패 확인 방법과 실패 시 대응 |

공통 동작은 이 절에서 설명하고 화면별 범위·형식·제한이 다르면 해당 화면에 명시한다. 내보내기 기능이 없는 화면에는 사용 절차를 작성하지 않는다.

---

**작성 예시 — 페이지별 Export 차이**

| 페이지 | 형식 | 범위 | 필터·정렬 | 제한 |
| --- | --- | --- | --- | --- |
| Performance Summary | CSV, Excel(.xlsx) | Detail의 전체 조회 결과 | 현재 조회 조건·정렬 반영 | 최대 10,000행 |
| Alarm History | CSV | 현재 페이지에서 선택한 행 | 현재 목록의 정렬 반영 | 페이지당 최대 100행 선택 |
| User Settings | 미지원 | 해당 없음 | 해당 없음 | 해당 없음 |

> Performance Summary에서 Export를 누른 후 CSV 또는 Excel을 선택하세요. 차트 이미지는 포함되지 않으며 Detail의 전체 조회 결과가 파일로 저장됩니다. 10,000행을 초과하면 파일을 만들지 않고 “내보내기는 최대 10,000행입니다”를 표시합니다. 조회 기간이나 설비 조건을 좁힌 후 다시 시도하세요.
>
> Alarm History에서는 현재 페이지에서 내보낼 행을 선택한 후 CSV를 누르세요. 다른 목록 페이지로 이동하면 행 선택이 해제됩니다. 선택한 행이 없으면 CSV 버튼을 사용할 수 없습니다.
>
> 파일의 시간대와 표시 단위는 화면과 같습니다. 브라우저의 다운로드 목록에서 완료 여부와 저장 위치를 확인하세요. 실패한 항목이 표시되면 연결 상태를 확인한 후 다시 내보내세요.

# 8. Drill-down / Log Tracking 작성 기준

사용자 매뉴얼에서는 내부 데이터 추적 구조를 설명하지 않는다.

다음 세 가지를 중심으로 작성한다.

1. 어디를 선택하는가
2. 어떤 화면이 표시되는가
3. 무엇을 확인할 수 있는가

예:

```text
Alarm Summary
      ↓ Alarm 선택
Alarm Detail
      ↓ Log 선택
Event Log
      ↓
발생 시간 / Equipment / Message 확인
```

DB, API, SQL 또는 내부 Reference Key 처리 방식은 제외한다.

Drill-down 동작 기준은 다음 표로 정리한다.

| 항목 | 설명할 내용 |
| --- | --- |
| 선택 위치 | 선택할 위젯·숫자·차트 지점·행 |
| 이동 대상 | 열리는 상세 화면 또는 팝업 |
| 조회 기간 전달 | 기존 기간 유지 여부 또는 선택한 시점에 따른 상세 시간 범위 |
| 조회 조건 전달 | 선택한 설비·상태 등의 상세 화면 반영 여부 |
| 뒤로 돌아오기 | 기존 화면의 필터·정렬·페이지 유지 여부 |
| 이동 제한 | 데이터 또는 권한이 없을 때 선택 가능 여부와 안내 |

공통 동작은 Common Functions에서 정의하고 각 화면의 Drill-down 절에는 선택 위치·이동 대상과 공통 기준에서 달라지는 동작을 작성한다. 특히 차트의 특정 시점을 선택할 때 상세 화면이 보여주는 시간 범위를 명확히 설명한다.

---

**작성 예시 — Performance Trend의 Drill-down 정책**

| 항목 | 사용자 매뉴얼에 넣을 설명 |
| --- | --- |
| 선택 위치 | Performance Trend의 데이터 지점을 선택합니다. |
| 이동 대상 | Performance Detail (`PERF-01-01`)이 열립니다. |
| 조회 기간 | `2026-09-03 10:00` 지점 선택 시 `10:00 이상~11:00 미만(KST)`의 기록이 표시됩니다. `11:00` 기록은 다음 구간에 포함됩니다. |
| 조회 조건 | 선택 중인 Equipment 조건을 유지합니다. All이면 모든 설비를 포함합니다. |
| 추가 이동 | 상세 기록에서 Log를 선택하면 해당 기록의 Performance Log (`PERF-01-02`)가 열립니다. |
| 복귀 | Back으로 돌아오면 기존 기간·설비·정렬·페이지가 유지됩니다. |
| 제한 | 값이 `-`인 지점은 선택할 수 없습니다. 상세 권한이 없으면 “접근 권한이 없습니다”가 표시됩니다. |

이 예시는 전체 조회 기간과 상세 조회 기간이 달라지는 경우다. “선택한 시점의 상세를 보여줍니다”로 끝내지 않고 실제 시간 범위까지 설명한다.

# 9. 화면 캡처 작성 기준

## 9.1 기본 수량

시스템 화면과 문서 페이지를 구분한다.

* 시스템 화면 기준: 전체 구성 캡처 1장을 기본으로 한다. 긴 화면은 10절에 따라 구간별로 분리한다.
* 문서 A4 한 쪽 기준: 부분 화면 / Widget / Popup은 2~3장을 권장하되 글자 가독성을 우선한다.
* 이미지가 많거나 작아 글자를 읽기 어려우면 다음 문서 페이지로 분리한다. 수량을 맞추기 위해 캡처를 과도하게 축소하지 않는다.

## 9.2 이미지 크기

동일한 종류의 캡처는 동일한 크기를 사용한다.

예:

* 전체 화면 → 동일 Width
* Widget → 동일 Width
* Popup → 동일 Width

이미지의 원본 Aspect Ratio는 유지한다.

## 9.3 촬영 환경

가능하면 동일한 조건에서 캡처한다.

* 동일 브라우저
* 동일 브라우저 크기
* 동일 해상도
* 동일 Zoom

---

## 9.4 캡처 내용 및 최종 가독성

* 개인정보·계정 정보·민감한 업무 데이터는 마스킹하거나 예시 데이터를 사용한다.
* 본문에서 설명하는 조회 조건·선택 상태와 캡처 상태를 일치시킨다.
* 최종 PDF 또는 인쇄 크기에서 화면 글자를 식별할 수 있는지 확인한다.
* 색상이나 Marker만으로 설명하지 않고 실제 버튼·항목 이름을 함께 표기한다.

---

**작성 예시 — 캡처 계획과 설명 연결**

| 캡처 ID | 촬영 내용 | 본문 연결 | 촬영 전 확인 |
| --- | --- | --- | --- |

| 단위 | % |
| 해석 | 값이 높을수록 집계 대상 시간 중 가동한 시간이 많습니다. |

**Appendix C — Utilization 계산 예시**

> 가동률(%) = 실제 가동시간 ÷ 집계 대상 시간 × 100
>
> 조회 기간 10시간 중 계획 정지 2시간을 제외하면 집계 대상 시간은 8시간입니다. 실제 가동시간이 6시간이면 `6 ÷ 8 × 100 = 75.0%`입니다.
>
> 집계 대상 시간이 0이면 비율을 계산할 수 없으므로 `-`를 표시합니다. 이는 가동률 `0.0%`와 다릅니다.
