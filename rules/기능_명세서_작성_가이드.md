# 기능 명세서 작성 가이드

이 문서는 사용자와 논의한 기능 명세서의 작성 기준을 정리한 것이다. 이전 목차안을 확장한 가이드이며, 실제 제품의 기능 명세서 자체는 아니다.

> 모든 화면명·ID·수치·지원 기능·오류 문구는 작성 방법을 설명하기 위한 가상 예시다. 실제 제품의 요구사항이나 검증 결과를 의미하지 않는다. 실제 작성 시 확정한 기준으로 바꾸고, 미확정 항목은 명시한다.

## 1. 문서 목적과 대상

기능 명세서는 **누가, 어떤 조건에서, 무엇을 하면, 시스템이 어떻게 동작해야 하는지**를 정의한다. 정상 동작뿐 아니라 입력 오류·결과 없음·권한 제한·실패 시 동작을 포함한다.

작성 완료를 판단하는 질문은 다음과 같다.

> 개발자가 동작을 구현하고, QA가 기대 결과와 비교하여 판정할 수 있는가?

### 주요 독자

| 독자 | 사용하는 목적 |
| --- | --- |
| 기획자·PM | 의도한 기능과 업무 규칙이 빠짐없이 정의됐는지 확인 |
| 개발자 | 입력·상태·결과·예외의 구현 기준 확인 |
| QA·테스터 | 정상·경계·실패 상황의 기대 결과 확인 |
| 디자이너 | 로딩·빈 상태·오류·권한 제한 등 필요한 화면 상태 확인 |
| 현업·발주 담당자 | 업무 요구와 요청한 기능의 반영 여부 검토 |

일반 사용자의 사용 안내는 사용자 매뉴얼에서 제공한다.

## 2. 다른 문서와의 구분

| 문서 | 책임지는 내용 | 조회 기능 설명 예시 |
| --- | --- | --- |
| 사용자 매뉴얼 | 사용 순서·화면 의미·주의사항 | 기간과 설비를 선택한 후 Search를 누르세요. |
| 기능 명세서 | 조건에 따른 동작·상태·결과·예외·완료 조건 | 입력 검증 후 조회한다. 로딩·성공·빈 결과·실패 상태를 구분한다. |
| API 명세서 | URL·Method·파라미터·요청/응답·오류 코드 | 어떤 요청을 보내면 어떤 데이터와 오류를 반환하는지 정의 |
| 지표·계산식 명세서 | 지표 정의·산식·집계 기준·포함/제외 조건 | Availability의 정확한 정의와 계산 대상 정의 |
| 데이터 명세서 | 원천·테이블/뷰·컬럼·관계·변환·갱신 기준 | 지표 계산에 사용하는 원천 데이터 구조 정의 |

### 기본 원칙

* 기능 명세서는 코드·SQL을 나열하는 문서가 아니다. 사용자에게 직접 보이지 않는 처리 과정도 동작 판단에 필요하면 정의한다.
* 화면 입력값의 필수 여부와 범위는 기능 명세서에 작성한다.
* API는 관련 이름·ID·링크를 연결하는 것을 기본으로 한다. 실제 요청 형식은 API 명세서를 원본으로 삼는다.
* 지표 산식은 기능 명세서에서 중복 정의하지 않는다. 지표 ID를 참조하고 화면 표시·상호작용을 작성한다.
* 전문 명세서와 기능 요구가 충돌하면 임의로 덮어쓰지 않고 담당자와 불일치를 해결한다.

조회 기능 하나가 여러 API를 사용할 수 있다.

```text
성능 조회 기능
├─ KPI 조회 API
├─ 추이 조회 API
└─ 상세 목록 조회 API
```

## 3. 전체 문서 구조

실제 메뉴 → 페이지 → 개별 기능 순서로 구성한다. 아래는 최종 기능 명세서의 목차 예시다.

```text
기능 명세서
├─ 1. 문서 개요
│  ├─ 목적·대상 독자
│  ├─ 대상 시스템·범위
│  └─ 관련 문서·용어
├─ 2. 페이지·기능 목록
├─ 3. 공통 기능 및 동작 기준
│  ├─ 로그인·권한·세션 만료
│  ├─ 조회·Search·Reset
│  ├─ 정렬·페이지 이동
│  ├─ 로딩·결과 없음·실패
│  ├─ 시간·데이터 표시
│  ├─ Drill-down·복귀
│  ├─ 저장·적용·취소
│  └─ CSV·Excel 내보내기
├─ 4. Monitoring
│  └─ Performance Summary [PERF-01]
│     ├─ 페이지 개요·구성·초기 상태
│     ├─ 조회 [PERF-F01]
│     ├─ KPI·차트・목록 표시 [PERF-F02]
│     ├─ Drill-down [PERF-F03]
│     └─ 내보내기 [PERF-F04]
├─ 5. History
│  └─ Alarm History [ALM-01]
│     ├─ 페이지 개요·구성·초기 상태
│     ├─ 알람 조회
│     ├─ 상세·로그 확인
│     └─ CSV 내보내기
├─ 6. Settings
│  └─ User Settings [SET-01]
│     ├─ 페이지 개요·구성·초기 상태
│     ├─ 설정값 입력·검증
│     └─ 저장·적용·취소
└─ 부록
   ├─ 용어·Reference Index
   ├─ 관련 API·지표·데이터 명세 연결
   ├─ 완료 조건·QA 시나리오 연결
   └─ 미확정 사항
```

존재하지 않는 기능은 넣지 않는다. 작은 문서에서는 부록 연결표를 개별 기능의 참조 항목으로 합칠 수 있다.

## 4. 작성 단위·기능 유형·식별자

### 4.1 작성 단위

**페이지 아래에 독립적으로 설명·검증할 수 있는 기능을 나누어 작성한다.** 모든 버튼을 별도 기능으로 쪼갤 필요는 없다. 공통으로 움직이는 입력·버튼·결과는 하나의 기능 흐름으로 설명할 수 있다.

사용자 매뉴얼의 Dashboard / Workflow / Configuration은 페이지 유형이다. 아래 유형은 페이지 안의 개별 기능을 분류한다.

### 4.2 기능 유형

| 유형 | 예시 | 특히 확인할 항목 |
| --- | --- | --- |
| 조회 | 검색·필터·목록 조회 | 조건·실행 시점·정렬·페이지 처리·빈 결과 |
| 표시·분석 | KPI·차트·Tooltip | 지표 참조·단위·갱신·데이터 없음 표기 |
| 상세 이동 | Drill-down·팝업·Log | 대상·전달 조건·시간 범위·복귀 상태 |
| 등록·변경·삭제 | 항목 등록·설정 저장·삭제 | 입력 검증·권한·적용 시점/범위·취소·실패 |
| 내보내기 | CSV·Excel | 형식·대상 범위·필터/정렬 반영·건수 제한 |

공통 템플릿을 유지하고 유형마다 필요한 항목을 추가한다. 복합 기능은 관련 유형의 항목을 함께 적용한다.

### 4.3 식별자 및 기능 목록 예시

ID는 페이지 번호와 분리하고, 문서에서 고유하게 식별할 수 있도록 부여한다. 기존 프로젝트 ID 규칙이 있다면 그 규칙을 사용한다. 아래 접두사는 예시다.

| 구분 | ID 예시 |
| --- | --- |
| 페이지 | PERF-01 |
| 기능 | PERF-F01 |
| 공통 기준 | COM-SEARCH-01 |
| 지표 | MET-001 |
| API | API-PERF-KPI |

| 페이지 | 기능 ID | 기능명 | 유형 |
| --- | --- | --- | --- |
| PERF-01 | PERF-F01 | 성능 조회 | 조회 |
| PERF-01 | PERF-F02 | KPI·차트·목록 표시 | 표시·분석 |
| PERF-01 | PERF-F03 | 시간대 상세 이동 | 상세 이동 |
| PERF-01 | PERF-F04 | CSV·Excel 내보내기 | 내보내기 |

## 5. 공통 기능과 중복 처리

### 5.1 중복 설명은 생략하되 적용 여부와 차이는 남긴다

| 내용 | 작성 위치 |
| --- | --- |
| Availability의 정의·산식 | 지표·계산식 명세서에 한 번 |
| 여러 페이지에서 같은 기간 필터 동작 | 공통 기능에 한 번 |
| 해당 페이지에서 사용하는 지표·필터 | 페이지 명세에서 참조 |
| 페이지별 기본값·적용 영역·동작 차이 | 해당 페이지에 작성 |

### 5.2 공통 기준 적용표 예시

아래 공통 기준은 구조 설명을 위한 가상 정의다.

| 공통 ID | 공통 기준 |
| --- | --- |
| COM-SEARCH-01 | 기간 필수, 기본값 오늘, 최대 30일. 조건 변경 후 Search로 적용 |
| COM-EQUIP-01 | All 또는 한 설비 선택. 기본값 All |
| COM-SORT-01 | 열 제목 선택 시 오름차순/내림차순 전환, 목록 첫 페이지로 이동 |

Performance Summary에 기본값 차이가 있는 경우:

| 항목 | 참조 기준 | 페이지별 차이 |
| --- | --- | --- |
| 기간 필터 | COM-SEARCH-01 | 최초 기본값만 최근 7일로 변경 |
| 설비 필터 | COM-EQUIP-01 | 없음 |
| 목록 정렬 | COM-SORT-01 | 없음 |
| Availability | MET-001 | 정의·산식 변경 없음. 표시 위치·클릭은 PERF-F02/F03 참조 |

> 페이지별 차이는 공통 기준의 어느 항목을 어떻게 변경하는지 명시한다. 차이가 기재되지 않은 항목은 공통 기준을 따른다.

지표의 업무 정의나 API 계약을 페이지 예외라는 이유로 임의 변경하지 않는다. 계산 기준 자체가 다르면 지표 명세서에서 구분한 정의를 참조한다.

## 6. 페이지 명세 템플릿

| 항목 | 작성할 내용 | Performance Summary 작성 예시 |
| --- | --- | --- |
| 페이지 ID·이름 | 고정 ID와 화면 표시명 | PERF-01 / Performance Summary |
| 메뉴 위치·목적 | 위치와 주요 업무 | Monitoring / 설비 가용률·추이 확인 |
| 사용자·권한 | 페이지와 기능별 접근 범위 | 성능 조회 권한, 내보내기는 별도 권한 |
| 화면 구성 | 화면 또는 설계안, 영역 번호 | ① 조건 ② KPI ③ 추이 ④ Detail |
| 초기 상태 | 기본값·최초 조회 여부 | 최근 7일, Equipment All, 최초 자동 조회 |
| 포함 기능 | 기능 목록 참조 | PERF-F01~PERF-F04 |
| 공통 기준·차이 | 적용할 공통 ID와 예외 | 5.2의 적용표 참조 |
| 영역 간 관계 | 어떤 조작이 어디에 반영되는지 | Search는 KPI·추이·Detail 모두에 적용 |
| 관련 지표 | 사용하는 지표 ID | Availability / MET-001 |

캡처는 실제 화면인지 설계안인지 표시하고 설명의 번호와 맞춘다. 이미지에만 동작 기준을 담지 않고 표·본문으로 명시한다.

해당 없는 항목은 해당 없음으로 표시하거나 양식에 따라 생략한다. 미확정과 해당 없음을 혼동하지 않는다.

## 8. 입력값·전달값·API 참조

### 8.1 파라미터를 어디까지 쓰나?

| 구분 | 기능 명세서에서 작성할 내용 |
| --- | --- |
| 화면 입력값 | 의미·필수 여부·기본값·허용 범위·오류 안내 |
| 화면 간 전달값 | 상세 이동 시 기간·설비·선택 기록 등의 의미 |
| API 파라미터 | API ID/링크 참조가 기본. 연결이 모호할 때만 매핑 표 추가 |

**입력 조건 작성 예시**

| 화면 항목 | 필수 여부 | 기본값 | 검증 기준 |
| --- | --- | --- | --- |
| Period | 필수 | 최근 7일 | 시작일·종료일 포함 최대 30일, 미래 날짜 불가 |
| Equipment | 필수 | All | All 또는 한 설비 |

필터에 All을 선택하면 전체 설비를 조회한다는 것은 기능 기준이다. 요청 필드 생략·null·특정 코드 중 어떤 방식으로 표현할지는 API 명세서에서 정한다.

### 8.2 선택적으로 작성하는 API 연결 예시

| 화면 값 | API 필드 예시 | 기능 의미 |
| --- | --- | --- |
| Period 시작일 | from | 조회 시작 기준 |
| Period 종료일 | to | 조회 종료 기준 |
| Equipment | equipmentId | 조회 대상 설비 |

필드명은 가상 예시다. 실제 타입·시간 형식·기간 경계의 전송 방식·요청/응답 예시는 API 명세서를 참조한다. API 내용을 기능 명세서의 별도 원본으로 유지하지 않는다.

## 9. 통계 지표와 필터 영향

### 9.1 지표 표시 명세

통계 화면에는 사용하는 지표 목록과 화면 동작을 작성한다. 이름만 보고 산식을 추정하지 않는다.

| 항목 | Availability 작성 예시 |
| --- | --- |
| 지표명·참조 | Availability / MET-001 |
| 표시 위치 | 상단 KPI와 시간별 추이 |
| 조회 조건 | Search에 적용한 기간·설비 |
| 표시 형식 | %, 소수점 첫째 자리. 표시 반올림 기준은 공통 표시 기준 참조 |
| 데이터 없음 | 계산 불가 데이터는 `-` 표시, 실제 0과 구분 |
| 갱신 | 최초 진입과 Search 성공 시 갱신 |
| 클릭 동작 | 추이 지점 선택 시 해당 시간대 상세 이동 |
| 산식·집계 | MET-001 참조. 여기서 다시 정의하지 않음 |

### 9.2 필터 영향표

조합마다 명세를 새로 작성하지 않고 어떤 필터가 어느 영역에 어떻게 적용되는지 표로 정의한다. 특별한 조합 제약이 있을 때만 별도 행이나 조건을 추가한다.

| 필터·조작 | KPI | 추이 차트 | Detail | 적용 시점 |
| --- | --- | --- | --- | --- |
| Period | 계산 대상 기간 변경 | 조회 기간 변경 | 기록 기간 변경 | Search |
| Equipment | 계산 대상 설비 변경 | 대상 설비 변경 | 대상 설비 변경 | Search |
| 목록 검색어 | 영향 없음 | 영향 없음 | 일치하는 행만 표시 | 입력 후 Enter |
| 목록 정렬 | 영향 없음 | 영향 없음 | 표시 순서 변경·첫 페이지 이동 | 열 제목 선택 |

**반드시 구분할 내용**

* 계산 대상 변경인지, 표시 방식·목록만 변경하는지.
* 모든 영역에 적용되는지, 특정 위젯에만 적용되는지.
* 선택 직후 적용인지, Search 이후 적용인지.
* 필터 간 연동이나 허용하지 않는 조합이 있는지.
* 계산식 자체가 달라진다면 어느 지표 정의를 참조하는지.

기간·설비 기본값과 일반 동작은 공통 기준을 참조하되 위 표처럼 페이지의 적용 범위는 남긴다.

## 10. 상태 변화·부분 실패·연속 조작

### 10.1 조회 조건 적용 시점

선택 중인 조건과 현재 결과를 만든 조건을 구분한다.

> 예시: Period를 변경하는 동안 현재 결과는 유지한다. “조건이 변경되었습니다. Search를 눌러 적용하세요”를 표시하고 결과 영역에는 마지막으로 적용한 조건을 표시한다. 유효한 조건으로 Search를 선택하면 새 조회를 시작한다.

### 10.2 처리 상태와 일부 영역 실패

다음은 PERF-F01 예시의 상태 정책이다.

| 상태 | 화면·버튼 동작 |
| --- | --- |
| 조회 시작 | 세 영역의 이전 결과를 제거하고 각 영역에 로딩 표시. Search 비활성화 |
| 영역 성공 | 해당 영역에 새 결과 표시 |
| 영역 결과 없음 | 해당 영역에 데이터 없음 표시. 지표 계산 불가이면 `-` |
| 영역 실패 | 해당 영역의 로딩 종료·실패 안내 표시. 다른 영역의 성공 결과 유지 |
| 모든 영역 처리 종료 | Search 활성화 |
| 실패 후 재조회 | Search로 세 영역 모두 다시 조회 |

동시에 적용된 결과는 같은 조회 조건에 속해야 한다. 실패를 0건이나 0%로 표시하지 않는다. 전체 성공만 허용하는 제품이라면 그 방식으로 명시한다.

### 10.3 연속 조작과 늦게 도착한 결과

* 조회 중 Search를 막는지, 새 조회를 허용하는지 명시한다.
* 새 조회가 허용되는 기능은 이전 결과가 늦게 도착했을 때 어떤 결과를 표시할지 정한다.
* 구현 방식은 강제하지 않고 최종 화면의 기대 동작을 적는다.

**별도 사례 — 선택 즉시 조회하는 설비 상세 패널**

> 이 사례는 조회 중 Search를 막는 PERF-F01과 별개의 정책 예시다. 설비 A 선택 후 B를 연속 선택하면 최종 화면은 B의 결과만 표시한다. A 응답이 나중에 도착해도 B 결과를 덮어쓰지 않는다.

저장·삭제 등 중복 실행이 결과에 영향을 주는 기능도 실행 중 버튼 상태와 반복 실행 처리 기준을 작성한다.

## 12. 완료 조건과 관련 명세 연결

### 12.1 완료 조건 작성법

“정상적으로”, “적절히” 같은 표현만으로 끝내지 않는다. 조건·조작·기대 결과를 구체적으로 적는다.

| 부족한 표현 | 검증 가능한 표현 |
| --- | --- |
| 조회가 잘 된다 | 동일 기간·설비로 조회한 KPI·차트·목록은 모두 적용한 조건의 결과를 표시한다. |
| 입력 오류 처리 | 시작일·종료일 포함 31일을 선택해 Search를 누르면 기간 초과 안내가 표시되고 조회되지 않는다. |
| 오류를 적절히 처리 | 차트만 실패하면 차트 로딩이 종료되고 실패 안내가 표시되며 성공한 KPI·목록은 유지된다. |
| 필터가 적용된다 | 목록 검색어를 적용해도 상단 Availability와 추이 차트는 변경되지 않는다. |
| 최신 결과를 표시 | 연속 선택을 허용하는 상세 패널에서 A 다음 B를 선택하면 늦게 도착한 A 결과는 B를 덮어쓰지 않는다. |

### 12.2 연결표 예시

아래 ID는 예시이며 실제 작성 시 존재하는 명세·시나리오로 연결한다.

| 기능 | 관련 기준/명세 | QA 시나리오 예시 |
| --- | --- | --- |
| PERF-F01 | COM-SEARCH-01, API-PERF-KPI/TREND/DETAIL | 정상 조회, 30일/31일, 부분 실패 |
| PERF-F02 | MET-001, 공통 데이터 표시 기준 | 값 형식, 실제 0과 계산 불가 구분 |
| PERF-F03 | 공통 Drill-down, 관련 상세 API | 시간 경계·조건 전달·복귀 상태 |
| PERF-F04 | 관련 Export API | CSV/Excel, 정렬·범위, 10,000/10,001행 |

기능 명세서는 기대 동작을 정의한다. 실제 검증 환경·실행 일자·통과/실패 결과는 QA 기록에 남기고 연결한다. 명세를 작성했다는 이유만으로 기능이나 검증이 완료됐다고 표시하지 않는다.

## 13. 작성 검토 기준

* 페이지·기능 ID와 이름이 목록·본문·참조에서 일치하는가?
* 최초 상태·기본값·실행 계기가 명확한가?
* 필수 입력·범위·오류 안내가 구현 가능한 수준인가?
* 권한과 처리 중 상태, 빈 결과·실패·재시도가 정의됐는가?
* 선택 중인 조건과 현재 결과의 적용 조건을 구분했는가?
* 필터가 어느 지표·차트·목록에 적용되는지 명확한가?
* 일부 영역 실패와 연속 조작에 필요한 기준이 있는가?
* 상세 전달 시간의 경계와 복귀 상태가 명확한가?
* 지표·API·데이터 정의를 중복 원본으로 만들지 않았는가?
* 공통 참조와 페이지별 차이가 명시돼 있고 서로 충돌하지 않는가?
* 완료 조건으로 정상·경계·실패 상황을 판정할 수 있는가?
* 예시와 실제 요구사항, 미확정과 검증 완료가 구분됐는가?

## 14. 기존 양식 확인 및 미확정 사항

문서 버전·적용 제품 버전·개정 이력·작성/검토자 등의 관리 양식은 기존 양식 유무를 확인한 뒤 반영한다. 이 가이드에서 새 관리 양식을 확정하지 않는다.

미확정 동작은 임의로 확정된 것처럼 작성하지 않는다. 다음은 기록 형태의 예시이며 기존 양식이 있으면 그 양식을 따른다.

| 미확정 항목 | 필요한 결정 | 담당 | 확정 필요 시점 |
| --- | --- | --- | --- |
| Availability 집계 정의 | 포함·제외 시간과 설비 합산 기준 | 지표 담당자·현업 | 지표 구현 전 |
| 조회 일부 실패 | 영역별 성공 허용 여부 | 기획·PM | 화면 상태 구현 전 |
| Export 한도 | 실제 허용 행 수 | 기획·개발 | 내보내기 구현 전 |

실제 적용 시 대표 페이지 하나를 작성하고 개발·QA 관점에서 누락·중복을 확인한 뒤 나머지 페이지로 확대한다.

| 메뉴 위치 | Monitoring → Performance Summary |
| 목적 | 기간·설비별 Availability와 시간별 추이를 확인하고 상세 기록을 조회한다. |
| 조회 권한 | 성능 조회 권한이 있는 사용자가 접근할 수 있다. 권한이 없으면 “접근 권한이 없습니다”를 표시하고 데이터를 조회하지 않는다. |
| 내보내기 권한 | 조회 권한과 별도다. 내보내기 권한이 없으면 CSV·Excel 버튼을 비활성화하고 “내보내기 권한이 필요합니다”를 표시한다. |
| 시간대 | 날짜와 시간은 KST를 사용한다. |
| 최초 진입 | 오늘을 포함한 최근 7일, Equipment All로 자동 조회한다. |
| 자동 갱신 | 최초 진입 이후 주기적 자동 갱신은 하지 않는다. Search로 다시 조회한다. |

예를 들어 기준일이 `2026-09-15`라면 최초 기간은 `2026-09-09~2026-09-15`다.

### 15.2 화면 구성과 기능 연결

다음은 구조를 설명하는 설계도이며 실제 화면 캡처가 아니다.

```text
┌─────────────────────────────────────────────────┐
│ ① Period / Equipment / Search / Reset           │
├─────────────────────────────────────────────────┤
│ 적용 조건: 2026-09-09~09-15 / All / KST          │
│ 조건 변경 시: Search를 눌러 적용하세요           │
├─────────────────────────────────────────────────┤
│ ② Availability KPI                              │
├─────────────────────────────────────────────────┤
│ ③ Performance Trend — 시간별 Availability       │
├─────────────────────────────────────────────────┤
│ ④ Detail 검색어 / 상세 목록 / 정렬 / 페이지      │
│                                  CSV / Excel    │
└─────────────────────────────────────────────────┘
```

| 영역 | 관련 기능 | 역할 |
| --- | --- | --- |
| ① 조회 조건 | PERF-F01 | 전체 페이지 조회 조건 선택·실행 |
| ② KPI | PERF-F02 | 적용 조건의 Availability 표시 |
| ③ 추이 | PERF-F02 / PERF-F03 | 시간별 값 표시와 시간대 상세 이동 |
| ④ Detail | PERF-F02 / PERF-F04 | 상세 목록 탐색과 내보내기 |

### 15.3 공통 기준 적용

| 항목 | 공통 참조 | 이 페이지의 차이 |
| --- | --- | --- |
| 기간 | COM-SEARCH-01 | 최초 기본값만 최근 7일. 최대 30일은 동일 |
| 설비 | COM-EQUIP-01 | 없음 |
| 목록 정렬 | COM-SORT-01 | 없음 |
| 지표 정의 | MET-001 Availability | 산식 변경 없음 |

예시에서 COM-SORT-01은 열 제목 선택 시 정렬 방향 전환·첫 페이지 이동을 뜻한다. 전문 명세인 MET-001의 산식은 이 페이지에서 다시 작성하지 않는다.

### 15.4 조회 조건과 적용 범위

| 항목 | 필수 여부 | 기본값 | 허용값·제약 | 적용 시점 |
| --- | --- | --- | --- | --- |
| Period | 필수 | 최근 7일 | 시작일 ≤ 종료일, 양 끝 날짜 포함 최대 30일, 미래 날짜 불가 | Search |
| Equipment | 필수 | All | All 또는 접근 가능한 설비 한 대 | Search |
| Detail 검색어 | 선택 | 빈 문자열 | 최대 50자, 앞뒤 공백 제외 후 설비명·메시지의 부분 일치 검색 | Enter |
| Detail 정렬 | 해당 없음 | 발생 시각 내림차순 | 발생 시각·설비명 열에 정렬 제공 | 열 제목 선택 |

| 조작 | KPI | 추이 | Detail |
| --- | --- | --- | --- |
| Period·Equipment를 바꾸고 Search | 새 조건 적용 | 새 조건 적용 | 새 조건 적용, 검색어 초기화·첫 페이지 이동 |
| Detail 검색어 Enter | 변경 없음 | 변경 없음 | 검색 결과로 갱신·첫 페이지 이동 |
| Detail 정렬 | 변경 없음 | 변경 없음 | 순서 변경·첫 페이지 이동 |
| Reset | 즉시 변경 없음 | 즉시 변경 없음 | 즉시 변경 없음 |

Reset은 입력 중인 Period를 최근 7일, Equipment를 All로 되돌린다. 아직 Search를 누르지 않았다면 표시 중인 결과와 Detail 검색어·정렬·페이지는 유지한다. 유효한 Search를 실행하면 Detail 검색어는 비우고 정렬은 발생 시각 내림차순, 페이지는 1로 초기화한다.

### 15.5 PERF-F01 — 성능 조회

**정상 흐름**

1. 최초 진입 또는 Search 선택 시 입력값을 검증한다.
2. 검증을 통과하면 실행 시점의 기간·설비를 이번 조회의 적용 조건으로 확정한다.
3. 기존 KPI·추이·Detail 결과를 제거하고 각 영역에 로딩을 표시한다.
4. 조회 중 Period·Equipment·Search·Reset과 Detail 조작을 비활성화한다.
5. 관련 API로 세 영역을 조회한다. 요청 형식은 API-PERF-KPI, API-PERF-TREND, API-PERF-DETAIL을 참조한다.
6. 각 영역은 완료되는 대로 결과 또는 실패 안내를 표시한다.
7. 모든 영역의 처리가 종료되면 조회 조건 조작을 활성화한다. 실패 영역이 있어도 Search로 전체 재조회할 수 있다.
8. 페이지를 떠난 뒤 도착한 응답은 떠난 화면을 다시 열거나 현재 화면을 변경하지 않는다.

**입력 오류**

| 조건 | 안내 | 결과 |
| --- | --- | --- |
| 기간 미입력 | 조회 기간을 선택하세요 | 조회하지 않고 기존 결과 유지 |
| 시작일이 종료일보다 늦음 | 시작일은 종료일 이후일 수 없습니다 | 조회하지 않고 기존 결과 유지 |
| 31일 이상 | 조회 기간은 최대 30일입니다 | 조회하지 않고 기존 결과 유지 |
| 미래 날짜 포함 | 미래 날짜는 조회할 수 없습니다 | 조회하지 않고 기존 결과 유지 |

**처리 결과**

| 결과 | 화면 동작 |
| --- | --- |
| 전체 성공 | 세 영역에 같은 적용 조건의 결과 표시 |
| 특정 영역에 데이터 없음 | 해당 영역에 데이터 없음 표시. 계산할 수 없는 KPI 값은 `-` |
| 차트만 실패 | 차트에 “추이를 불러오지 못했습니다” 표시. 성공한 KPI와 Detail 유지 |
| 전체 실패 | 각 영역에 실패 안내 표시. 전체 로딩 종료 후 Search 재활성화 |

재조회 시 실패 영역만 재요청하는 별도 버튼은 제공하지 않는다. Search는 세 영역을 모두 다시 조회한다.

**조작 예시**

| 순서 | 사용자 행동·발생 상황 | 기대 화면 |
| --- | --- | --- |
| 1 | 09-09~09-15 / All 조회 성공 | 세 영역에 All 기준 결과 |
| 2 | Equipment를 OHT-01로 변경 | 결과는 All 유지, 조건 변경 안내 표시 |
| 3 | Search 선택 | OHT-01 적용 조건 표시, 세 영역 로딩 |
| 4 | KPI·Detail 성공, 추이 실패 | KPI·Detail은 OHT-01 결과, 추이만 실패 안내 |
| 5 | Search 재선택 | OHT-01 조건으로 세 영역 재조회 |

### 15.6 PERF-F02 — 지표·차트·목록 표시

| 대상 | 표시 기준 |
| --- | --- |
| Availability KPI | MET-001 값을 %로 표시. 소수점 둘째 자리에서 반올림하여 첫째 자리까지 표시 |
| 실제 0 | `0.0%` 표시 |
| 계산 불가 | `-` 표시. 실제 0과 구분 |
| 추이 | 1시간 구간으로 표시. 데이터 없는 구간은 선으로 이어 채우지 않음 |
| Tooltip | 구간 시작·종료(KST), 적용 설비 조건, Availability 표시 |
| Detail | 발생 시각·설비명·메시지 표시. 행 수는 저장된 목록 페이지 크기 설정 적용, 최초 기본값 20 |
| 동일 시각 정렬 | 발생 시각이 같으면 기록 ID 오름차순을 보조 기준으로 사용. 기록 ID는 화면에 표시하지 않아도 됨 |

다음은 지표 계산을 시험하는 데이터가 아니라 **응답을 화면에 표시하는 규칙의 예시**다. Availability의 산식 검증은 MET-001을 기준으로 별도 수행한다.

| 표시용 입력 | 기대 표시 |
| --- | --- |
| 98.26%에 해당하는 값 | 98.3% |
| 실제 측정·계산 결과 0% | 0.0% |
| 지표 명세상 계산 불가 | - |
| API 실패 | 실패 안내. 0.0%나 -로 대체하지 않음 |

### 15.7 PERF-F03 — 시간대 상세 이동

| 항목 | 명세 |
| --- | --- |
| 실행 위치 | 추이 차트의 유효한 지점 |
| 이동 대상 | Performance Detail |
| 전달 기간 | 선택한 지점의 1시간 구간. 시작 포함·종료 제외 |
| 전달 설비 | 입력 중인 값이 아니라 차트 결과에 적용된 Equipment |
| 전달 제외 | Detail 목록 검색어·정렬은 차트 상세 조건으로 전달하지 않음 |
| 값 없음 | `-` 구간은 상세 선택 불가 |
| 복귀 | 기존 적용 조건·입력 중 조건·조건 변경 안내·Detail 검색어·정렬·페이지 복원 |

**시간 경계 예시**

`2026-09-10 10:00 / OHT-01` 지점을 선택한 경우:

| 기록 | 상세 포함 여부 |
| --- | --- |
| 09:59:59 / OHT-01 | 제외 |
| 10:00:00 / OHT-01 | 포함 |
| 10:59:59 / OHT-01 | 포함 |
| 11:00:00 / OHT-01 | 제외 |
| 10:30:00 / STK-01 | 제외 |

상세를 연 뒤 복귀했을 때 기존 Detail이 3페이지였다면 3페이지로 돌아온다. 설비 필터를 수정했지만 Search를 누르지 않은 상태였다면 그 미적용 입력과 안내도 함께 복원한다.

### 15.8 PERF-F04 — CSV·Excel 내보내기

| 항목 | 명세 |
| --- | --- |
| 실행 | CSV 또는 Excel 버튼 선택 |
| 형식 | CSV는 `.csv`, Excel은 `.xlsx` |
| 데이터 범위 | Detail의 전체 검색 결과. 현재 목록 페이지만 내보내지 않음 |
| 조건 | 결과에 적용된 Period·Equipment·Detail 검색어 |
| 정렬 | 현재 Detail의 정렬 및 보조 정렬 기준 |
| 미적용 입력 | Search를 누르지 않은 기간·설비 변경값은 제외 |
| 최대 행 수 | 헤더를 제외한 데이터 10,000행 |
| 초과 | “내보내기는 최대 10,000행입니다” 표시, 파일 생성하지 않음 |
| 실행 제한 | 권한 없음·조회 중·Detail 실패·결과 0행일 때 비활성화 |
| 생성 중 | 두 내보내기 버튼 모두 비활성화하여 중복 생성 방지 |
| 성공·실패 | 생성 종료 후 버튼 재활성화. 실패 시 안내 후 다시 실행 가능 |

**입력과 파일 결과 예시**

| 현재 화면 상태 | 파일에 포함할 내용 |
| --- | --- |
| 적용 설비 OHT-01, 입력 중 설비 STK-01, Search 미실행 | OHT-01 결과 |
| Detail 3페이지, 전체 검색 결과 65행, 페이지 크기 20 | 65행 전체 |
| Detail 검색어 “장애”, 결과 8행 | “장애” 검색 결과 8행 |
| 발생 시각 오름차순 | 파일도 같은 오름차순 |
| 결과 10,000행 | 데이터 10,000행과 헤더 생성 |
| 결과 10,001행 | 제한 안내, 파일 없음 |

CSV와 Excel 모두 같은 데이터 범위·시간대·표시 단위를 사용한다. 파일 내용에 KPI 카드나 차트 이미지는 포함하지 않는다.

## 16. 추가 예시 — 공통 기능 재사용과 설정 저장

### 16.1 다른 페이지에서 중복을 줄이는 방법

Alarm History에서도 기간·설비 필터를 사용한다면 공통 규칙을 복사하지 않고 아래처럼 적는다.

| 페이지 | 적용 항목 | 참조 | 차이 |
| --- | --- | --- | --- |
| Performance Summary | 기간 | COM-SEARCH-01 | 최초 기본값 최근 7일 |
| Alarm History | 기간 | COM-SEARCH-01 | 없음: 공통 기본값 오늘 |
| 두 페이지 | 설비 | COM-EQUIP-01 | 없음 |

이 표는 입력 규칙의 재사용을 보여준다. “참조하므로 아무것도 적지 않는다”가 아니라 **무엇을 적용했는지와 무엇이 다른지 남기는 것**이다. Alarm History의 검색 결과·상세 이동·내보내기 범위는 해당 기능에서 따로 정의해야 한다.

### 16.2 User Settings — 설정 저장의 구체적 결과

예시 항목은 11.4와 같은 **목록 기본 페이지 크기**다.

| 항목 | 명세 |
| --- | --- |
| 현재 저장값 | 20 |
| 선택 가능값 | 20, 50, 100 |
| 화면 진입 | 현재 저장값을 선택한 상태로 표시 |
| Save | 선택값 검증 후 저장. 처리 중 Save·값 선택·Cancel 비활성화 |
| 저장 성공 | “저장되었습니다” 표시, 새 값이 현재 저장값이 됨 |
| 저장 실패 | “저장에 실패했습니다. 다시 시도하세요” 표시. 선택값 유지, 저장값은 그대로 |
| Cancel | 선택값을 현재 저장값으로 복원 |
| 적용 | 다음 목록 화면 진입부터 내 계정에 반영 |
| 미저장 이탈 | “변경 내용을 저장하지 않고 나가시겠습니까?” 확인. 나가기면 버리고 이동, 계속 편집이면 유지 |

**시나리오별 값 변화**

각 행은 저장값 20인 상태에서 독립적으로 시작한다.

| 사용자 행동·결과 | 화면 선택값 | 실제 저장값 | 다음 목록 진입의 페이지 크기 |
| --- | --- | --- | --- |
| 50 선택, Save 전 | 50 | 20 | 미저장 이탈을 확인하고 나가면 20 |
| 50 선택, Save 성공 | 50 | 50 | 50 |
| 50 선택, Save 실패 | 50 | 20 | 미저장 이탈을 확인하고 나가면 20 |
| 50 선택, Cancel | 20 | 20 | 20 |
| 50 선택, 화면 이탈에서 계속 편집 | 50 | 20 | 이동하지 않음 |
| 50 선택, 화면 이탈에서 나가기 | 화면 종료 | 20 | 20 |

완료 조건 예시: 저장 실패 후에도 사용자의 선택값 50이 남고, 재시도 성공 전에는 저장값과 다음 목록의 기본 페이지 크기가 20으로 유지되어야 한다.
